# REUSE_MAP — O que o RADAR reaproveita do Plane

> Fase 0 · Prompt 0.1 · 2026-10-03 · branch `radar-phase-0-spike`
> Análise somente leitura. Base factual: [PLANE_MAP.md](./PLANE_MAP.md). Riscos: [DOMAIN_COUPLING.md](./DOMAIN_COUPLING.md).

## Classificação

| Classe                        | Significado                                                                                                                                                                        | Custo para o RADAR                                                      |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **R1** · Reusar como está     | Consumir sem tocar em arquivos do Plane.                                                                                                                                           | ~0                                                                      |
| **R2** · Reusar via seam      | Reusar o código; exige um adaptador do lado RADAR e/ou um toque pequeno e localizado num arquivo do Plane (adicionar membro a união/enum, item a uma lista, branch a um `switch`). | Baixo. Cada toque vira um _touch point_ rastreado (DOMAIN_COUPLING §4). |
| **R3** · Referência de padrão | O código está acoplado a Issue/Project; o RADAR copia o **padrão** e implementa o seu.                                                                                             | Médio (código novo).                                                    |
| **R4** · Não reusar           | Domínio Plane. Fica no fork intacto (para não gerar conflito de merge), mas fora do caminho do RADAR.                                                                              | 0 (ignorar).                                                            |

Regra de fronteira proposta: o **RADAR Core** só referencia `db.Workspace`, `db.User` e, para arquivos, `db.FileAsset`. Nenhuma FK do Core aponta para `Project`, `Issue` ou qualquer `ProjectBaseModel`.

## 3. Não reusar (R4) — mantidos intactos no fork

`Project`, `Issue`/WorkItem e satélites (`Issue*`), `State`, `Estimate`, `Cycle`, `Module`, `IssueView`, `Intake`, `DraftIssue`, archives, analytics de issue, `apps/space`, `IssueRelation`, `IssueType`/`ProjectIssueType`, `issue_activities_task`, `notification_task`, webhooks de entidade.

Não apagar: remover código do Plane aumenta conflitos ao trazer upstream. Se for preciso esconder, esconder pela navegação (dock item / sidebar), não por deleção.

| `components/issues`                                                                                                                   | 322      | 210 (65%) |
| `store/issue`                                                                                                                         | 44       | 32 (73%)  |

A heurística é um limite superior: conta também `projectId` opcional (ex.: `member-select.tsx`, `comments/*` funcionam sem ele). Ainda assim, os ativos de shell e UI genérica estão praticamente desacoplados. O acoplamento se concentra onde era esperado: `issues/*`, `store/issue/*` e os pipelines de backend de activity/notification.


## Atualização 0.3A — primitives seguras e uso efetivo

Classificações R4 de BaseModel / AuditModel / SoftDeleteModel permanecem fechadas. O Core implementado herda diretamente de django.db.models.Model, não dessas classes.

| Primitive | Classe | Decisão no slice |
| --- | --- | --- |
| TimeAuditModel | R1 | Inspecionado: somente timestamps; redeclarados no RadarBaseModel para não importar o módulo misto com tarefas Celery. |
| UUID uuid4 | R1 (padrão) | UUIDField próprio. |
| ChangeTrackerMixin | R1 | Inspecionado, sem ator implícito; não necessário nesta etapa. |
| Campos UserAuditModel | R2 (referência) | FKs próprias preenchidas explicitamente pelos commands. |
| validate_html_content | R1 | Sanitização nh3 independente de Project/Issue no Command Layer. |
| BaseListLayout / RichTextEditor / Select / Dialog / Toast | R1 | Reuso confirmado com dados reais; nenhuma mudança nos componentes do Plane. |
